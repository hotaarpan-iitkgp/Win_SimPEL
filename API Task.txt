Implementation Plan: SimPEL Python API
Problem statement
Win_SimPEL has a capable engine, but nothing outside the GUI can drive it. Block knowledge is spread over about 10 places, and the netlist generator lives in the UI layer. The CSV exporter is dead code. The exporters and pin definitions are tied to ImGui. An API built on top of this would break every time a block changes. So the work is two things: give the tool a headless core with a single block registry, then put a Python API on top of it.

Requirements (from your answers)
Ship a Python module built with pybind11 on a C++ core library.
Describe circuits by connectivity only: blocks, parameters and pin-to-pin connections, with no coordinates.
Use a single block registry as the source of truth. The GUI, the netlist generator and the API all read it, so adding a block is a data change.
Analyses:
transient
signal stats
Fourier/THD
loss analysis
CSV/SVG/HTML export
parameter sweeps run in parallel
Not in v1: AC/Bode, Monte Carlo, steady-state.
Waveforms in Python (NumPy, pandas, matplotlib). Results can also be saved and opened in the GUI scope.
Auto-layout, so designs built in Python open in the GUI as readable schematics.
The design must keep working as blocks are added or changed.
Background (what I found)
Headless pipeline. One already exists in main.cpp (processSingleJsonFile): load → buildNodesForCircuit → generateNetlistJson → parseJsonString → setup/reset/runTransient → telemetry → SVG/HTML.

Blockers to a headless library

generateNetlistJson (~2,100 lines) sits in src/ui. Its header includes imgui.h.
getTerminals() is defined in SchematicCanvas.cpp.
SVGExporter uses ImVec2 and Win32 file dialogs.
There is one monolithic CMake target with static MinGW linking.
Block knowledge is duplicated

There are two ComponentType enums (176 and 164 values).
There are 4 or more string→type mappers. One has shadowing bugs: "PID"→PI_Controller, "SIGN"→Sign, and others.
The palette has no pins, units or ranges.
Pins are defined in two places.
The netlist emitter whitelists parameters per type and silently drops unknown types (PI_SECTION, LINE_3PH).
MOSFET Ron has three different defaults.
Results. SimulationOutput has structured maps, but setTelemetryOutput flattens them. pause() is a stub and there is no cancel. LossModelLibrary::loadAllModels() is only called by the GUI.

Prior art in the parent repo

config.ts COMPONENT_PINS and detailedLibrary.ts (183 entries) can seed the registry.
routing.ts has an A* router: 20 px grid, turn penalty 150.
No auto-placer exists anywhere in the repo.
Test assets


Toolchain risk. Official CPython is built with MSVC and the GUI is built with MinGW. The engine sources look portable: the only Win32 include is guarded by #ifdef _WIN32.

Task breakdown
Task 1: Golden-output regression harness

Objective: lock current behaviour before any refactor.
Guidance:
Add a tests/golden/ C++ runner that reuses the processSingleJsonFile pipeline. It loads a design, runs the transient and writes a digest per signal: sample count, a hash of the doubles, min/max/RMS.
Pick about 30 designs from working jsons/ that cover the categories: power stage, control, magnetics, CScript, three-phase, CHB. Add the 5 from regression_tests/.
Add a CTest target, plus a --update flag to regenerate the references.
Tests: the harness passes against the references it just generated. An intentional parameter tweak makes it fail.
Demo: ctest -R golden runs about 35 designs and prints pass/fail per signal.
Task 2: Extract the simpel_core static library

Objective: build an engine library with no ImGui dependency that the GUI links.
Guidance:
Move the getTerminals definition into 
Terminals.cpp
.
Move generateNetlistJson into 
NetlistGenerator.cpp
. Its body has no ImGui calls. Leave a thin forwarding call in NetlistSourceView.
In CMake, add a simpel_core STATIC target (engine plus the moved files). circuitsim_pro_win links it. Add a simpel_cli target built from the runHeadlessCLI code.
Add a CMake check that fails if any core source includes imgui.
Tests: golden digests unchanged; the GUI builds and runs; test_wiring passes 14/14.
Demo: simpel_cli -i Buck_converter.json -o out/ produces the same HTML as before, built without ImGui.
Task 3: MSVC + pybind11 spike (toolchain de-risk)

Objective: prove the core builds with MSVC and loads into official CPython.
Guidance:
Add a python/ folder with pyproject.toml (scikit-build-core, pinned pybind11).
Build simpel._core, exposing version() and run_design_file(path, t_stop, dt) -> dict[str, np.ndarray].
Fix any MSVC portability issues in the engine, such as M_PI, VLAs or GNU extensions.
If MSVC fails badly, fall back to MinGW with a matching MinGW Python and document that choice.
Tests: pytest checks that run_design_file on the Buck design matches the golden digest from Python. The golden suite also runs under the MSVC build, and any digest drift between compilers gets recorded and explained.
Demo: pip install -e python/ then import simpel; simpel._core.run_design_file("Buck_converter.json") returns NumPy arrays.
Task 4: Unified DesignIO

Objective: one design loader and serializer that persists simulation settings.
Guidance:
Add src/engine/DesignIO.{hpp,cpp}. It replaces the three copies of buildSchematicJsonString and the loaders.
On read, accept simulationSettings, simulation_parameters and simulation_settings. Always write simulationSettings.
Point the GUI, CLI and the Python spike at it.
Tests: a round trip of load → save → load over all 421 corpus files gives an identical in-memory model. Golden digests unchanged.
Demo: save a design in the GUI, reopen it, and the step type and tolerances are kept.
Task 5: Block registry schema, loader and seed data

Objective: one data-driven spec for every block, readable by every layer.
Guidance:
Add data/blocks/<category>.json. Each entry has:
type, aliases, category/subcategory, label
pins (name, domain electrical/control/magnetic, side, offset, direction)
dynamicPins hook name
params (name, type, default, unit, min/max, options, aliases)
engineType, emitter (generic or a named custom emitter)
Write a one-off seed script that merges allComponents, getTerminals, config.ts and detailedLibrary.ts. Commit only the generated JSON.
Add a BlockRegistry C++ class: lookup by type or alias, plus schema validation at load.
Bind it to Python straight away: sp.blocks() and sp.block_info("MOSFET").
Tests:
Registry consistency test: every palette type is present, every type maps to an engine enum, no alias collides with another type (this catches the shadowing bugs), and every default is within range.
Golden digests unchanged, because nothing reads the registry yet.
Demo: sp.block_info("MOSFET") prints pins, parameters, units and defaults.
Task 6: Registry drives type mapping and pins

Objective: remove the 4 string→type mappers and the duplicate pin tables.
Guidance:
Replace stringToComponentType, the mapper in NetlistParser.cpp, and the clipboard mapper with registry lookups.
getTerminals and setupComponentPins read static pins from the registry. Dynamic-pin blocks (PROBE, SUBSYSTEM, XFMR, CSCRIPT, SUM_RECT) keep code hooks, which the registry names.
Resolve the shadowing bugs explicitly. Keep the current engine behaviour (PID→ContinuousPID) and record each decision in the registry.
Tests: golden digests unchanged; test_wiring passes; a new pin test compares registry pins with the old getTerminals output for every type.
Demo: the GUI places and wires every block exactly as before.
Task 7: Registry drives the palette and inspector

Objective: the GUI palette, defaults and dropdowns come from the registry.
Guidance:
Build allComponents at startup from the registry.
Remove the hard-coded dropdown options (MainWindow.cpp:2765-2806).
The inspector shows units and enforces ranges.
Settle on a single MOSFET Ron default. Existing files keep their stored values.
Tests: the palette lists the same 166 entries with the same categories. Golden digests unchanged, since stored designs carry explicit parameters.
Demo: add a test parameter to a block's JSON and it appears in the GUI inspector without recompiling.
Task 8: Registry-driven netlist emission

Objective: adding a block or parameter no longer needs code changes in the emitter.
Guidance:
Add a generic emitter that passes through every parameter declared in the registry, with alias renames.
Port the per-type branches of generateNetlistJson to generic wherever the output is byte-identical. The rest stay as named custom emitters.
Types with no emitter now cause a validation error instead of being dropped silently. This covers PI_SECTION and LINE_3PH.
Write 
adding-a-block.md
. Target: 1 JSON entry for simple blocks, plus engine code only when the physics is new.
Tests:
The netlist JSON is byte-identical for every corpus design before and after.
Golden digests unchanged.
Adding a new parameter to the registry shows up in the netlist.
Demo: the netlist diff over 421 designs is empty.
Task 9: C++ facade Circuit and Python bindings

Objective: build circuits programmatically by connectivity.
Guidance:
Circuit::add(type, id, params) returns a handle with typed pins.
Also connect(pin, pin), ground(pin) and named nets.
validate() checks for an unknown type or parameter, out-of-range values, unconnected required pins, floating nodes, and domain mismatches (electrical vs control).
The facade converts to the design model through DesignIO, with coordinates at zero, and then to a netlist.
The pybind11 layer adds __getattr__ pin access (q1.d) and **kwargs parameters checked against the registry.
Tests:
Build Buck_converter.json in Python by hand and confirm the netlist matches the file's netlist after node renumbering.
The run matches its golden digest.
Validation error tests.
Demo: a 15-line Python script builds the buck and prints the netlist.
Task 10: Simulation and Results with progress and cancel

Objective: run transients from Python and get structured, NumPy-native results.
Guidance:
SimulationSettings covers t_stop, dt, step type, tolerances and the list of wanted signals.
Replace the pause() stub with an atomic cancel flag, checked in the step loop.
Report progress through a callback that is throttled and acquires the GIL.
Results keeps the SimulationOutput categories (voltages, ammeters, signals and so on) rather than the flattened telemetry. Data is exposed zero-copy as NumPy through buffer protocol views.
Release the GIL during run().
Also provide to_pandas(), signals() and __getitem__.
Tests: Results arrays equal the golden digests; cancel returns within one step batch and leaves partial results; Ctrl+C in Python cancels; the GUI's own run still works.
Demo: build, run and view res.to_pandas() in a Jupyter notebook.
Task 11: Analyses (stats, Fourier/THD, losses)

Objective: make every existing analysis available headlessly.
Guidance:
Bind computeSignalStats and computeFourierSpectrum as res.stats() and res.fourier(), with THD, harmonics and phase.
Make the LossModelLibrary data directory configurable (environment variable or sp.set_data_dir) and load it lazily on first use.
res.losses() wraps LossAnalysisEngine::runAnalysis and returns a per-device DataFrame of conduction and switching losses.
Move the duplicated interpolateSignal into core.
Tests:
Stats and Fourier values match the GUI's numbers for 3 designs, within 1e-12.
Losses match the GUI and are cross-checked against loss engine/loss_engine.py on one MOSFET case.
Demo: compute the efficiency of the buck from res.losses() in Python.
Task 12: Exports and plotting

Objective: export CSV, SVG and HTML from Python, and draw quick plots.
Guidance:
Port exportCSVData into core and drop the dead CLIProcessor.
Split SVGExporter: replace ImVec2 with a POD Vec2, and move the Win32 dialogs into the UI layer.
Add res.export_csv/svg/html.
Add res.plot() in pure Python with matplotlib as an optional dependency. Long traces are min/max decimated using TracePlotter::decimateMinMax, bound from C++.
Tests: the CSV re-read equals the arrays; the HTML from Python matches the CLI output; the GUI export dialog still works.
Demo: a notebook that runs the buck, plots the inductor ripple and writes report.html.
Task 13: Thread-safety audit and parallel sweeps

Objective: run parameter sweeps safely in parallel.
Guidance:
Audit the statics and singletons in CScriptEngine, ExpressionEvaluator, LossModelLibrary and the RNG blocks. Make them per-instance, or read-only after load.
Add a C++ thread pool. sweep(circuit, grid|list, settings, workers, keep="metrics"|"all") clones the circuit per point, runs with the GIL released, and returns a DataFrame.
Metrics: declarative built-ins such as {"V_Cout": ["mean", "pp"]} are computed in C++. Python callables run afterwards in the main thread.
Tests: parallel results are bitwise equal to serial for 16 points, including a CScript design and a seeded-noise design; a stress run with 8 workers × 50 points under a sanitizer-like repeat; cancelling stops all workers.
Demo: a 2-D Ron × L sweep with 24 points, a heat map of output ripple, and the measured speedup vs serial.
Task 14: Auto-layout placement

Objective: designs built in Python open in the GUI with sensible placement.
Guidance:
Add 
Placer.cpp
. It uses layered left-to-right placement: sources on the left, the power path ranked by graph distance from them, and two-terminal parts placed vertically between rails, with ground at the bottom.
Control blocks go in their own band below, ordered by signal flow. Probes sit next to their target.
Snap to the 20 px grid, take bounds from registry pins, and add a deterministic tiebreak.
Emit simple orthogonal L-wires (a port of getOrthogonalPath) so the result is usable immediately.
Python: c.save(path, layout="auto").
Tests: no overlapping bounds and everything on-grid for all corpus designs after stripping coordinates; deterministic output; the reloaded design gives an identical netlist.
Demo: a Python-built buck opens in the GUI with readable placement and L-wires.
Task 15: A wire router*

Objective: clean, mostly non-overlapping wiring.
Guidance:
Port findAStarPath from routing.ts to C++. Use a binary heap and an occupancy grid that marks bodies and existing wires.
Keep the turn penalty, add a crossing and overlap cost, and use pin exit directions from the registry.
Route nets largest first, and fall back to L-wires when the iteration cap is hit.
Tests: no wire passes through a component body; the number of crossings is reported. Benchmark: a 3-phase CHB (about 60 switches) routes in under 1 s.
Demo: before/after screenshots of the CHB auto-layout in the GUI.
Task 16: Open results in the GUI scope

Objective: view Python results in the GUI scope.
Guidance:
Define a .simres format: a JSON header (version, signal names, categories, settings, design hash) followed by contiguous float64 blocks. Write and read it in core.
GUI: add File → Open Results, which loads into telemetry, bumps telemetryGeneration and opens the scope. Also accept a --results command-line argument.
Python: res.save_for_gui() and sp.open_in_gui(design, results), which launches the exe.
Tests: a write → read round trip is bitwise; the GUI loads a 1M-sample file; a design-hash mismatch shows a warning.
Demo: a sweep in Python, then the worst point opens in the GUI scope with one call.
Task 17: Packaging, docs and the stability contract

Objective: make the API shippable and safe to evolve.
Guidance:
Build a wheel with data files (registry, thermal models). Add sp.__version__ and a registry schema version.
Generate per-block docs from the registry (sp.block_info, plus a Markdown export).
Write 4 example notebooks: build, analyse, sweep, GUI round trip.
Add a CI script that runs golden, pytest and registry-consistency checks.
Deprecation policy: parameter aliases in the registry keep old names working when blocks change.
Tests: the full pytest suite and golden suite in a clean venv install.
Demo: pip install simpel-*.whl on a clean machine, then run the example notebooks.
Risks
MSVC portability, or numeric drift between compilers. Task 3 surfaces this early.
The registry refactor touches the GUI. Each step is gated by the golden digests and byte-identical netlists.
Hidden global state in CScriptEngine or ExpressionEvaluator could break parallel sweeps. Task 13 audits it before sweeps ship.
Auto-layout quality on large or dense circuits. Placement is a heuristic, so plan to iterate on it.
